Control de versiones

Definición

Sistema que registra los cambios hechos a los archivos de un proyecto a lo largo del tiempo, permitiendo volver a versiones anteriores, comparar cambios y trabajar en equipo sin sobrescribir el trabajo de otros.

Tipos de sistemas

Local (RCS): las versiones se guardan en el equipo del usuario.

Ventajas: simple y rápido. Desventajas: no permite colaboración y un fallo del disco pierde todo.

Centralizado (SVN, CVS): un servidor único guarda el historial; los usuarios extraen y envían cambios.

Ventajas: control de accesos y administración sencilla. Desventajas: depende del servidor y requiere conexión; punto único de fallo.

Distribuido (Git, Mercurial): cada desarrollador tiene una copia completa del repositorio con todo su historial.

Ventajas: trabajo sin conexión, ramas rápidas y respaldo natural. Desventajas: curva de aprendizaje mayor y repositorios grandes pesan más.

Funcionamiento

Se trabaja en el directorio de trabajo, se agregan cambios al área de preparación (staging) y se confirman en el repositorio mediante commits. Cada commit tiene un identificador único (hash), autor, fecha y mensaje. Las ramas permiten desarrollar funciones en paralelo y luego unirlas (merge).

Rastreo y gestión de cambios

Con git status, git diff y git log se ve qué cambió, quién y cuándo. git revert deshace un commit y git blame muestra el autor de cada línea. Plataformas como GitHub o GitLab añaden pull requests e issues para revisar y dar seguimiento.

Ejemplo

git init
git add .
git commit -m "Primer commit"
git branch nueva-funcion
git checkout nueva-funcion
git merge main
git remote add origin URL
git push -u origin main

Persistencia y acceso a datos

Definición y características

Es la capacidad de una aplicación de conservar su información después de cerrarse o reiniciarse el dispositivo. Características: durabilidad, integridad, consistencia, acceso eficiente y seguridad.

Formas de persistencia en móviles

  • Archivos: texto, JSON, XML o binarios en almacenamiento interno o externo. También preferencias clave-valor (SharedPreferences, UserDefaults).
  • Bases de datos locales: SQLite, Room, Realm; guardan datos estructurados en el dispositivo.
  • Bases remotas vía servicios web: API REST/GraphQL hacia servidores o nube (Firebase, MySQL, PostgreSQL); requieren conexión.

Tipos de datos según la persistencia

FormaDatos típicos
Archivos / preferenciasConfiguraciones, textos, JSON, imágenes, caché
SQLite localDatos relacionales: usuarios, productos, historial
Servicios webDatos compartidos entre usuarios, sincronizados y centralizados

Mecanismos de control de acceso

Biblioteca de clases: APIs del SDK para leer/escribir (File, Context, FileProvider).

Clases de SQLite: SQLiteOpenHelper, SQLiteDatabase y Cursor para crear tablas y ejecutar consultas.

Mapeo relacional de objetos (ORM): convierte tablas en objetos de código (Room, Core Data, Hibernate), evitando escribir SQL manual.

Autenticación y consumo de servicios web

  1. El usuario envía credenciales.
  2. El servidor valida y devuelve un token (JWT/OAuth2).
  3. La app guarda el token de forma segura.
  4. Cada petición HTTP incluye el token en el encabezado Authorization.
  5. La app procesa la respuesta JSON.

Se usan librerías como Retrofit, Volley o Axios.

Ejemplo

fetch("https://api.ejemplo.com/usuarios", {
  headers: { "Authorization": "Bearer " + token }
}).then(r => r.json()).then(console.log);

Gestión de sensores

Definición

Los sensores son componentes de hardware que miden magnitudes físicas del entorno o del dispositivo y las convierten en datos que la aplicación puede usar.

Tipos de sensores

  • De movimiento: acelerómetro, giroscopio.
  • De posición: GPS, magnetómetro (brújula), proximidad.
  • Ambientales: luz, temperatura, humedad, presión (barómetro).
  • Biométricos y de entrada: huella, cámara, micrófono.

Proceso de gestión

  1. Habilitación: declarar permisos y solicitar autorización al usuario; comprobar que el sensor existe.
  2. Obtención: obtener el administrador (SensorManager) y registrar un listener con una frecuencia de muestreo.
  3. Procesamiento: filtrar ruido, convertir unidades, interpretar los valores y actualizar la interfaz.
  4. Liberación: cancelar el listener para ahorrar batería.
window.addEventListener("devicemotion", e => {

});

Uso de recursos multimedia

Definición

Son elementos que combinan texto, imagen, audio, video y animación para enriquecer la experiencia de la aplicación.

Tipos aplicables a la programación móvil

  • Imágenes: PNG, JPG, WebP, SVG.
  • Audio: MP3, AAC, OGG.
  • Video: MP4, WebM.
  • Animaciones: Lottie, GIF, animaciones de propiedades.
  • Elementos visuales dinámicos: gráficos, Canvas, transiciones.

Estructura del proyecto

Se guardan en carpetas dedicadas: res/drawable, res/raw, res/mipmap (Android), Assets.xcassets (iOS) o assets/ (Flutter, React Native).

Componentes de software

MediaPlayer y ExoPlayer (audio/video), VideoView, ImageView, Glide/Picasso (carga de imágenes), Canvas y Animator, y AVFoundation en iOS.

Servicios y notificaciones

Definición

Un servicio es un componente que ejecuta operaciones sin interfaz visible; una notificación es un mensaje que la app muestra al usuario fuera de su pantalla.

Tareas en segundo plano

Procesos que se ejecutan sin que el usuario interactúe: sincronizar datos, descargar archivos o reproducir música. Se implementan con Services, WorkManager, Coroutines o hilos.

Tratamiento de notificaciones

Se crea un canal, se construye la notificación (título, texto, ícono, acción) y se muestra. Pueden ser locales o push (FCM, APNs). Desde Android 13 se requiere permiso del usuario.

Proceso de implementación

  1. Proveedores de contenido: extender ContentProvider, definir URI y declararlo en el manifiesto.
  2. Tareas en segundo plano: crear un Worker y programarlo con restricciones (red, batería).
  3. Notificaciones: crear canal, construir con NotificationCompat y lanzar con NotificationManager.

Servicios en la nube

Firebase (base de datos, autenticación, mensajería), AWS Amplify, Google Cloud y Azure Mobile Apps ofrecen almacenamiento, autenticación, funciones y notificaciones push.

Librerías y toolkits para desarrollo móvil

¿Qué es una librería y qué es un toolkit?

Una librería es un conjunto de funciones reutilizables que se invocan desde el código. Un toolkit es un conjunto más amplio de herramientas, componentes y librerías para construir aplicaciones completas.

Librerías especializadas

  • Retrofit, Axios: red.
  • Room, Realm: datos.
  • Glide, Picasso: imágenes.
  • Gson, Moshi: JSON.
  • Dagger/Hilt: inyección de dependencias.

Depuración y seguridad

¿Qué es?

Depuración: proceso de encontrar y corregir errores del código.

Seguridad: conjunto de prácticas para proteger datos, comunicaciones y la app: cifrado, HTTPS, permisos mínimos, almacenamiento seguro de tokens y ofuscación de código.

Herramientas de depuración

  • Logcat / Log: mensajes del sistema y de la app.
  • Breakpoints y depurador de Android Studio y Xcode.
  • Profiler: CPU, memoria y red.
  • Emuladores y simuladores y adb.
  • Chrome DevTools / Flipper para apps web o híbridas.
